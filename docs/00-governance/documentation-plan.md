## 1. Inventory approach
The blueprint in the Master Prompt (section 8) is the coverage target. Each file is created only when it has real content; merges are allowed where duplication would result and are recorded in the decision log. The inventory is generated by `tools/` once written; `PROJECT_STATUS.md` tracks status per stage.

## 2. Stages and gates
Stages 0 to 11 as in the Master Prompt. Each stage ends with: validation, tracker update, commit, verified push.

## 3. Research strategy
1. Priority sources: IAEA, NRC (e.g. NUREG education material, Westinghouse-PWR descriptions), DOE, NEA, national labs, recognised textbooks (e.g. Lamarsh; Todreas and Kazimi; Incropera; Cengel).
2. Every source recorded once in the source registry with ID, issuer, identifier, URL, access date, category, claims supported, limits. Entries not actually opened are marked `UNV`.
3. Numeric representative PWR values are taken only from cited documents; otherwise left as documented gaps.
4. Thermophysical property data (water/steam) require a documented source (e.g. IAPWS-IF97) and validity range before use in the simulator spec.
5. Disagreements between sources are logged with applicability rationale.

## 4. Known risks
Volume vs. quality; fabricated citations (mitigation: `UNV` marking and registry-only citing); safety-boundary drift (mitigation: Stage 7 boundary doc and audit keyword check).
